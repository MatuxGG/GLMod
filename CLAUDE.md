## 0. Language rule (MANDATORY)

**The entire project is written and maintained in English. No exceptions.**

This rule applies to:
- **Source code**: identifiers (classes, methods, fields, properties, variables, parameters), file names, namespaces.
- **Comments**: single-line (`//`), multi-line (`/* */`), and XML doc comments (`///`).
- **Log messages** sent via `GLMod.log(...)`, `_logger.LogInfo(...)`, or any logging facility.
- **String literals** used for diagnostics, errors, and developer-facing messages.
- **Commit messages**, branch names, PR titles, and PR descriptions.
- **Documentation**: this `CLAUDE.md`, `README.md`, `docs/dev.MD`, and any other repository documentation.
- **Configuration keys** in BepInEx config files.

### Exceptions
- **Translation files**: `GLMod/Resources/Translations/<language>.json` hold the player-facing texts of the menu in each language (French in `fr.json`, etc.). Their **values** are in the file's language; their keys stay English, and `en.json` is the reference. Code never contains non-English player-facing text: it uses translation keys (§3.12).
- **Auto-generated files**: `GLMod/Properties/Resources.Designer.cs` is regenerated by Visual Studio in the developer's UI culture. Do not hand-edit; if it must be regenerated, do so on a machine configured with English UI.

### Enforcement
Any code review MUST reject contributions that introduce non-English identifiers, comments, or developer-facing strings. When updating existing code, opportunistically translate any leftover non-English content you encounter.

## 1. Project overview

### 1.1 Identity
- **Name**: GLMod (Good Loss Mod)
- **Current version**: `5.5.0` (see [GLMod/GLMod.csproj](GLMod/GLMod.csproj) and [GLMod/GLMod.cs](GLMod/GLMod.cs))
- **BepInEx plugin Id**: `glmod`
- **Author**: Matux
- **License**: GNU GPLv3
- **Repository**: https://github.com/MatuxGG/GLMod
- **Remote service**: [Good Loss](https://goodloss.fr) — Discord: https://goodloss.fr/discord

### 1.2 Purpose
GLMod is an **open source mod for Among Us** that collects match data and uploads it to the **Good Loss** platform in order to:
- Provide a **complete match history** per player.
- Compute and display detailed **statistics** (kills, exiles, votes, tasks, etc.).
- Maintain a **ranking system** (ranks) per mod.
- Enable **third-party integration**: other Among Us mods can override GLMod to record their custom roles and actions.

### 1.3 Supported platforms
- **Game OS**: Windows and Linux (via Proton/Wine).
- **Platform**: **Steam only** (identification is based on `SteamID`). No other platform (Epic, mobile, console) is supported.
- **Targeted Among Us version**: see `<GameVersion>` in [GLMod/GLMod.csproj](GLMod/GLMod.csproj) (currently `2026.3.31`). The README documents the downloadable release version (must be synchronized with every release).
- **Runtime**: .NET 6.0 (`net6.0`).

### 1.4 Main runtime dependencies
- **BepInEx** (IL2CPP) — Plugin injection framework for Unity IL2CPP.
- **HarmonyLib** — Runtime patching of Among Us methods.
- **Il2CppInterop.Runtime** — Managed C# ↔ IL2CPP bridge.
- **Steamworks.NET** — Reads the local SteamID.
- **Hazel** — Among Us internal network RPC system.
- **UnityEngine** — Coroutines, GameObjects, MonoBehaviour.
- **System.Text.Json** — Serialization / deserialization of API payloads.

The required DLLs are referenced via wildcard in the csproj:
```xml
<Reference Include="..\Among Us\BepInEx\core\*.dll" />
<Reference Include="..\Among Us\BepInEx\interop\*.dll" />
```

## 2. Architecture

### 2.1 Architectural pattern
GLMod follows a **service-oriented architecture** with:
- **Interfaces** in `GLMod/Services/Interfaces/` (contracts).
- **Implementations** in `GLMod/Services/Implementations/` (logic).
- **Manual dependency injection** in `GLMod.Load()` ([GLMod/GLMod.cs](GLMod/GLMod.cs)).
- **Static access** from the outside via the static properties of the `GLMod` class (e.g. `GLMod.AuthService`, `GLMod.GameStateManager`).

### 2.2 Lifecycle
1. `BasePlugin.Load()` is invoked by BepInEx when the game starts.
2. `InitializeConfiguration()` — binds the BepInEx `ConfigEntry<string>` instances (BepInEx/config/glmod.cfg).
3. `InitializeServices()` — instantiates the services (order matters, see dependencies below).
4. `VerifyStartupServices()` — logs the status of each service.
5. `ConfigureDefaultSettings()` — enables the default services (see §3.3).
6. `CoroutineRunner.Init()` — creates a persistent `DontDestroyOnLoad` GameObject to run coroutines from outside `MonoBehaviour`s.
7. `InitializeMenu()` — registers the built-in menu tabs (Account, Last game, Sessions) and attaches `MenuBehaviour` through `BasePlugin.AddComponent` (see §8.1).
8. `Harmony.PatchAll()` — applies all Harmony patches from the `GLMod.EventPatch` namespace.

### 2.3 Service dependency graph
```
AuthenticationService     ← ManualLogSource, ConfigEntry<string> connectionState, apiEndpoint
ConfigurationService      ← ManualLogSource, configPath
GameStateManager          ← Logger, AuthService, ConfigService, apiEndpoint, stepRpc
ServiceManager            ← (none)
ItemService               ← Logger, AuthService, apiEndpoint
RankService               ← Logger, AuthService, ConfigService, apiEndpoint
IntegrityService          ← Logger, apiEndpoint
MapService                ← Logger
GameHistoryService        ← Logger, history file path (config folder), max entries
MenuService               ← (none)
PlayerService             ← Logger, apiEndpoint
TranslationService        ← Logger, language provider (GameLanguage.CurrentCode)
```

### 2.4 Coroutines & async
- API calls use Unity **coroutines** (`IEnumerator`) to remain compatible with the Unity main thread.
- The bridge between `Task`-based async work and coroutines is centralized in [GLMod/Class/CoroutineHelpers.cs](GLMod/Class/CoroutineHelpers.cs) (`RunAsync<T>` / `RunAsync`). It encapsulates the `Task.Run` + volatile `done` flag + `yield return null` pattern. **Do not re-implement this pattern** elsewhere.
- See [GLMod/Class/ApiService.cs](GLMod/Class/ApiService.cs) (`PostFormAsync`, `PostFormWithErrorHandlingAsync`) for typical usage.
- `IIntegrityService` additionally exposes **async/await** variants (`*Async`) for consumers running outside a Unity context.
- `CoroutineRunner` ([GLMod/Class/CoroutineRunner.cs](GLMod/Class/CoroutineRunner.cs)) is a `MonoBehaviour` singleton registered in IL2CPP via `ClassInjector.RegisterTypeInIl2Cpp`.

## 3. Services

Every service is exposed statically via the main `GLMod` class and has a dedicated interface.

### 3.1 `IAuthenticationService` — [Interfaces/IAuthenticationService.cs](GLMod/Services/Interfaces/IAuthenticationService.cs)
- **Role**: handle Steam → Good Loss authentication.
- **Endpoint**: `POST {API}/user/login` with `steamId`.
- **HTTP codes**:
  - `200` → token returned in `response.Content`.
  - `403` + body prefixed `"Banned: "` → user is banned, reason follows the prefix.
  - Others → silent failure.
- **Exposed state**: `Token`, `IsLoggedIn`, `IsBanned`, `BanReason`.

### 3.2 `IServiceManager` — [Interfaces/IServiceManager.cs](GLMod/Services/Interfaces/IServiceManager.cs)
- **Role**: enable / disable **data collectors** (see enum `ServiceType`).
- **Services enabled by default** at startup (`ConfigureDefaultSettings`):
  - `StartGame`, `EndGame`, `Tasks`, `TasksMax`, `Exiled`, `Kills`,
  - `BodyReported`, `Emergencies`, `Turns`, `Votes`, `Roles`, `Shield`.
- A third-party mod can disable a service to override its behaviour (see `docs/dev.MD`).

### 3.3 `IGameStateManager` — [Interfaces/IGameStateManager.cs](GLMod/Services/Interfaces/IGameStateManager.cs)
- **Role**: state machine of the match lifecycle + uploads game data to the API.
- **Properties**: `CurrentGame` (GLGame), `Step` (GameStep), `GameCode`, `GameMap`.
- **Key methods**:
  - `StartGame(code, map, ranked)` — initializes a `GLGame`.
  - `SetRanked(ranked)` — updates the ranked flag on the current game (`bool` setter; stored as `"0"`/`"1"`).
  - `AddPlayer(name, role, team, color)` — adds a player to the current match.
  - `SendGame(onComplete)` — uploads the match to the API (coroutine).
  - `SyncGameId(onComplete)` — broadcasts the match ID to non-hosts via RPC.
  - `AddMyPlayer(onComplete)` — registers the local player on the server.
  - `GetShieldPlayer(onComplete, onError)` — returns the player who would have benefited from a T1 shield (retries on HTTP 400).
  - `SetWinnerTeams(winners)` / `AddWinnerPlayer(name)` — sets the outcome.
  - `EndGame()` — closes the match server-side.
  - `AddAction(source, target, action)` — records an action (kill, vote, sabotage, custom…).
  - `ResetGame()` — resets the state (`Step = Initial`).
- **Free play is never recorded nor sent**: in free play (`PlayModeHelper.IsFreePlay()`, i.e. `AmongUsClient.NetworkMode == NetworkModes.FreePlay`) the vanilla start trigger (`PlayerControlPatch`) does nothing, `StartGame` creates no game (`CurrentGame = null`), and `SendGame` / `AddMyPlayer` / `EndGame` send nothing — also when a third-party mod calls them itself.

### 3.4 `IItemService` — [Interfaces/IItemService.cs](GLMod/Services/Interfaces/IItemService.cs)
- **Role**: fetch unlocked items (achievements) and owned Steam DLCs.
- **Methods**: `ReloadItems()`, `IsUnlocked(id)`, `ReloadDlcOwnerships()`, `HasDlc(appId)`.

### 3.5 `IRankService` — [Interfaces/IRankService.cs](GLMod/Services/Interfaces/IRankService.cs)
- **Role**: fetch a player rank for a given mod.
- **Method**: `GetRank(modName, onComplete)` — `modName = null` ⇒ uses the current mod.

### 3.6 `IIntegrityService` — [Interfaces/IIntegrityService.cs](GLMod/Services/Interfaces/IIntegrityService.cs)
- **Role**: verify DLL integrity via remote checksum.
- **Endpoint**: `POST {API}/data`. A checksum is the `/data` entry whose id is `checksum_<checksumId>`, e.g. `checksum_glmod<version>` for GLMod itself (`VerifyGLMod`). There is no dedicated `/checksum` call.
- **Methods**:
  - Coroutines: `GetApiData`, `GetChecksum`, `VerifyDll`, `VerifyGLMod`.
  - Async: `GetApiDataAsync`, `GetChecksumAsync`, `VerifyDllAsync`, `VerifyGLModAsync`.
- **Third-party use**: Among Us Ranked calls `VerifyDllAsync("glmod", "BepInEx\plugins\GLMod.dll")` at startup and **quits the game** (integrity error, `Application.Quit`) when the hash differs, which is always the case for a locally built GLMod.

### 3.7 `IConfigurationService` — [Interfaces/IConfigurationService.cs](GLMod/Services/Interfaces/IConfigurationService.cs)
- **Role**: determine the host mod name.
- **Logic**: `FindModName()` scans `BepInEx/config/*.glmod`. If no `.glmod` file is found, `ModName = "Vanilla"`.
- **Manual override**: `SetModName(modName)` (used by third-party mods in their `Load()`).

### 3.8 `IMapService` — [Interfaces/IMapService.cs](GLMod/Services/Interfaces/IMapService.cs)
- **Role**: resolve the current map name.
- **Logic**: reads `GameOptionsManager.Instance.currentGameOptions.MapId`, maps it via `GameMapType` + special case `Dleks → "dlekSehT"`.

### 3.9 `IGameHistoryService` — [Interfaces/IGameHistoryService.cs](GLMod/Services/Interfaces/IGameHistoryService.cs)
- **Role**: local history of the games played with GLMod. **Never sent to the API.** It is no longer displayed (the menu reads sessions and the last game from the API, §3.11); its `EntryRecorded` event is the "a game just ended" signal of the menu (Last game tab selected and polled, sessions invalidated), and the E2E test checks it.
- **Storage**: `BepInEx/config/glmod-history.json` (`GAME_HISTORY_FILE_NAME`), most recent first, `GAME_HISTORY_MAX_ENTRIES` games. Written through a uniquely named temporary file then moved (several instances may share the config folder). An unreadable file gives an empty history.
- **Recording**: `EndGameManager.SetEverythingUp` postfix ([EndGameManagerPatch.cs](GLMod/EventPatch/EndGameManagerPatch.cs)), once per `CurrentGame`: game id, recap URL (`ApiEndpointResolver.GameRecapUrl(GLMod.api, id)`, so preprod games link to preprod), map, mod, local player's role / team, win (`EndGameResult.CachedWinners` contains `IsYou`). Works for host and clients, and whatever `ServiceType`s are enabled.
- **Members**: `Entries`, `Latest`, `Load()`, `Record(entry)` (replaces an older entry with the same game id), event `EntryRecorded`.
- Pure list logic (add / dedupe / truncate / JSON) lives in [GameHistoryList.cs](GLMod/Class/GameHistoryList.cs) (unit-tested).

### 3.10 `IMenuService` — [Interfaces/IMenuService.cs](GLMod/Services/Interfaces/IMenuService.cs)
- **Role**: state of the Good Loss menu — registered tabs (`IMenuTab`), selected tab, open/closed, enabled. **Public API for mods built on GLMod** (documented in `docs/dev.MD`):
  - **hide the menu completely**: `Enabled = false` (no chip, no panel, F2 / arrows / clicks left to the game, menu closed; `Open()` ignored). `IsVisible` = enabled **and** at least one tab (removing every tab also hides it); `IsOpen` is always false while not visible;
  - **remove tabs**, built-in ones included: `UnregisterTab(id)` / `UnregisterTab(tab)`; `FindTab(id)`;
  - **add tabs**: `RegisterTab(tab)` / `RegisterTab(id, title, draw, onShown)` (end of the bar), `InsertTab(index, tab)` (index clamped; the selected tab stays selected);
  - `Select(tab)` / `Select(id)`, `SelectNext` / `SelectPrevious` (wrap around), `Open` / `Close` / `Toggle`.
- **Tab ids**: every `IMenuTab` has a unique, stable `Id`; a tab without id or with an id already registered is refused. Built-in ids: `GameConstants.MENU_TAB_ACCOUNT` / `MENU_TAB_LAST_GAME` / `MENU_TAB_SESSIONS`. Third-party ids should be prefixed with the mod name (`mymod.rules`).
- Pure logic, no Unity dependency (unit-tested). Drawing and input are in `MenuBehaviour` (§8.1). Main thread only.

---

### 3.11 `IPlayerService` — [Interfaces/IPlayerService.cs](GLMod/Services/Interfaces/IPlayerService.cs)
- **Role**: read a player's public data on Good Loss for the menu.
- **Endpoints** (GET, no authentication, `?username=<Good Loss account name>` — `AuthService.GetAccountName()`):
  - `GetSessions` → `GET {API}/player/sessions` — the last 10 sessions (`GLSessionList`).
  - `GetLastGame` → `GET {API}/player/last-game` — the last finished game and the player's stats in it (`GLLastGame`).
- **Nullable fields**: the API sends `null` for values that do not exist yet (e.g. `end` of a live session) or do not apply; the entities use nullable types for every such number, otherwise the whole response would be unreadable.
- **Errors**: `{"error":"Player not found"}` (404) / `{"error":"Missing username"}` (400) are passed to `onError` as their message; a non-JSON error (e.g. the endpoint does not exist yet on production) gives `HTTP <code>`, a network failure `Network error`, a body that does not match the entities `Unreadable response` (the log then gives the JSON error and the start of the body).
- Requests go through `ApiService.GetWithErrorHandlingAsync` (also feeds `ServerClock`); parsing is pure ([PlayerApiResponse.cs](GLMod/Class/PlayerApiResponse.cs), unit-tested with captured preprod responses).
- **API**: the regular `GLMod.api` (production, or the `GLMOD_API_ENDPOINT` override). As long as the endpoints are not deployed on an API, it answers 404 and both tabs show "Unavailable (HTTP 404)".

### 3.12 `ITranslationService` — [Interfaces/ITranslationService.cs](GLMod/Services/Interfaces/ITranslationService.cs)
- **Role**: texts of the menu in the language selected in the game. **Every player-facing text of the menu goes through it** (`Get(key)`, `Get(key, args)` with `{0}` placeholders); tab titles too, so they follow language changes.
- **Language**: `GameLanguage.CurrentCode()` maps `DataManager.Settings.Language.CurrentLanguage` (`SupportedLangs`) to a code (`en`, `fr`, `pt-BR`, `es-419`, `zh-Hans`…); `MenuBehaviour` calls `RefreshLanguage()` every frame, so a change in the game settings applies at once. Unknown / not loaded yet → `en`.
- **Fallbacks** ([TranslationTable.cs](GLMod/Class/TranslationTable.cs), pure, unit-tested): language → base language (`pt-BR` → `pt`) → English → the key itself.
- **Texts**: embedded JSON files `GLMod/Resources/Translations/<language>.json` (flat `{"key": "text"}`, LogicalName prefix `TRANSLATION_RESOURCE_PREFIX`), loaded at startup. Shipped: `en` (reference, every key) and `fr` (every key; recent vanilla role names stay English where the official French name is not known). A unit test checks that each language only uses English keys and that French translates every non-role key. **Adding a language = adding a JSON file** with the same keys.
- **Mods**: `AddTranslations(language, texts)` adds their own keys (or a new language for GLMod's keys); `Has(key)`, `Language`.
- **Not translated**: data from the API (map names, mod names, non-vanilla role names, API error messages), the "GOOD LOSS" brand. Vanilla role names use the `role.<Name>` keys. Dates use the system culture.

## 4. Domain entities (`GLMod/GLEntities/`)

| Class           | Role                                                          |
|-----------------|---------------------------------------------------------------|
| `GLGame`        | Match model: id, code, map, modName, ranked, winner, turns, players, actions. |
| `GLPlayer`      | Player model: login, playerName, role, team, tasks, tasksDead, tasksMax, win, positions, color. |

| `GLData` / `GLDataList` | Generic key/value wrappers for API responses. |
| `GLJson`        | Static helpers `Serialize<T>` / `Deserialize<T>` (System.Text.Json) with try/catch + log. |

> **Note**: every numeric property transiting through the API is **encoded as `string`** (`tasks = "0"`, `ranked = "1"`, etc.). This convention matches the Good Loss API protocol and **must not be changed** without coordination with the API team. `GLGameHistoryEntry` is local-only and uses plain `long` / `bool`. The `/player/sessions` and `/player/last-game` responses are real JSON numbers / booleans / nulls: their entities mirror them (`long`, `int?`, `double?`, `bool?`) and their property names match the JSON keys exactly (camelCase, System.Text.Json is case-sensitive).

## 7. Harmony patches (`GLMod/EventPatch/`)

Patches are applied automatically via `Harmony.PatchAll()` at the end of `Load()`. Each file contains classes decorated with `[HarmonyPatch(...)]`.

| File                          | Main targets                                           |
|-------------------------------|--------------------------------------------------------|
| `AmongUsClientPatch.cs`       | Hooks on the Among Us network client (host/non-host).  |
| `InnerNetClientPatch.cs`      | RPC reception.                                         |
| `MainMenuManagerPatch.cs`     | Post-main-menu initialization.                         |
| `PlayerControlPatch.cs`       | Player actions (kill, report, vote, tasks…).           |
| `MeetingHudPatch.cs`          | Meeting cycle (vote, exile).                           |
| `ExileControllerPatch.cs`     | Exile animation and turn rollover.                     |
| `RPC.cs`                      | Manages **CustomRPC 240** (`HandleRpc`). Contains `GLRPCProcedure.makeRpcCall` and `handleRpc`. |
| `EndGameManagerPatch.cs`      | `EndGameManager.SetEverythingUp` postfix: records the game in the local history (§3.9). |
| `KeyboardJoystickPatch.cs`    | `KeyboardJoystick.Update` prefix: while the menu is open and an arrow key is held, the player does not move (arrows navigate the menu). |
| `PassiveButtonManagerPatch.cs`| `PassiveButtonManager.Update` prefix: skipped while the mouse is over the menu label / panel, so clicks do not reach the game buttons underneath. |

### 7.1 Custom RPC
- **Reserved ID**: `240` (`CustomRPC.HandleRpc`).
- **Payload format**: `int id`, `int count`, then `count` × `string value`.
- **Known RPC cases** (see `RPC.cs`):
  - `1`: non-hosts receive the match `GameId`.
  - `2`: `DisconnectInternal` → builds reason `DC_INTERNAL_<value>`.
  - `3`: `HandleDisconnect` → builds reason `DC_HANDLE_<value>`.
  - `4`: `OnDisconnect` → builds reason `DC_ON_<value>`.
  - (additional cases must be documented as they are added — **update this table**).

> Any new RPC ID must be **reserved here** before implementation to prevent collisions.

| `PlayModeHelper.cs`    | `IsFreePlay()` — free play games are never recorded nor sent (§3.3). |
| `StatFormat.cs`        | Pure formatting of menu stats: durations ("1 min 05 s", "2 h 05"), ratios, Yes/No, numbers, local dates, vanilla role names. |
| `ServerClock.cs`       | `NowMs()` — Unix ms aligned on the API server clock. The offset is refreshed from the `Date` header of every `ApiService` response. **Every timestamp sent to the API (actions, positions) must use `ServerClock.NowMs()`**, never `DateTimeOffset.UtcNow`. |
| `CoroutineHelpers.cs`  | `RunAsync` / `RunAsync<T>` — async-task ↔ coroutine bridge. Use these instead of re-implementing the `Task.Run` + volatile `done` flag pattern. |
| `CoroutineRunner.cs`   | `MonoBehaviour` IL2CPP singleton used to run coroutines from static classes.               |
| `ServiceLogger.cs`     | `Log(logger, serviceName, message)` — shared log formatter producing `[GLMod][Service] PlayerName: message`. Every service must delegate to it. |
| `BackgroundEvents.cs`  | Background loop: watches DCs, hidden sabotages, etc.                                       |
| `VanillaEvents.cs`     | Default implementations (`startGameVanilla`, `endGameVanilla`…) used when the matching `ServiceType` is enabled. |

### 8.1 Good Loss menu (`GLMod/Menu/`, namespace `GLMod.Menu`)

- **At rest**: a small dark "GOOD LOSS" chip (22 px high at 1080p, 12 px text, tight padding) **flush with the bottom edge of the screen** near the left corner (only its top corners are rounded), with a slowly breathing accent bar (55 % opacity), on every screen (menu, lobby, game, meetings, end screen). On hover it lights up, glows and widens to reveal the `F2` keycap. Hidden while the menu is not visible (`IMenuService.Enabled = false` or no tab).
- **Open / close**: `F2` (`MENU_TOGGLE_KEY`) or a click on the chip; `F2` or the **×** button closes it. The panel slides in from the left with a slight overshoot (0.32 s, ease-out-back, fading in) and slides out in 0.2 s; it is anchored bottom-left.
- **Look** (esport style): vertical gradient panel with a violet halo and an accent line on the top edge; header with the Good Loss logo (embedded `GLMod/Resources/goodloss-logo.png`, 110×128, decoded with `ImageConversion.LoadImage`; a gradient "GL" badge if it cannot be loaded), "GOOD LOSS" and the GLMod version; uppercase tabs with a glowing gradient indicator that glides to the selected tab; tab content fades and slides in from the side of the newly selected tab (0.22 s); keycap hints in the footer (`← →` tabs, `↑ ↓` scroll, `F2` close).
- **Fonts**: OS fonts through `Font.CreateDynamicFontFromOSFont`: display text (titles, tabs, buttons, captions) in Bahnschrift SemiBold (condensed DIN-like face of Windows 10+), body text in Segoe UI; Arial / the IMGUI default font elsewhere (Linux / Proton).
- **Navigation**: left / right arrows (or the ‹ › buttons, or a click on a tab) switch tabs; up / down arrows and the mouse wheel scroll the current tab. The game does not see these inputs while the menu uses them (§7 patches).
- **Rendering**: IMGUI from `MenuBehaviour` (`Update` = keys, scrolling, slide and content animations; `OnGUI` = drawing). Layout values are 1080p reference units converted to **screen pixels** with `MenuUI.U` (scale = screen height / 1080, never below `0.85`); styles (font sizes) are rebuilt when the scale changes, so text is rendered at its real size and stays sharp (no `GUI.matrix` scaling). Palette based on the Good Loss site (`--accent #A78BFA`, deeper `#7C3AED` for gradients, dark navy surfaces). `MenuBehaviour` notifies `IMenuTab.OnShown()` when a tab becomes visible; tab exceptions are logged once and replaced by an error message.
- **Widgets**: [MenuUI.cs](GLMod/Menu/MenuUI.cs) — public, used by built-in and third-party tabs: `Heading`, `Highlight`, `Label`, `Muted`, `Field`, `Button`, `Row`, `ProgressBar`, `Tiles`, `StatGrid` (compact 3-column stat tiles, null values skipped), `Tags` (colored pills, wrapping), `Space`, `Separator`, colors. Internal helpers for the built-in tabs: `Reserve`, `DrawRect`, `DrawGlow`, `DrawCircle`, `DrawAccentGradient`, `DrawPill`, `DrawSecondaryButton`, `EmptyState`.
- **Textures**: generated once with `Texture2D.SetPixel` (white, tinted through `GUI.backgroundColor` and drawn with `GUI.Box` + 9-slice borders): rounded rectangles (4 / 7 / 12 px), circle, soft halos (large and small), accent and panel gradients (colors baked in). A halo whose 9-slice border is larger than the drawn rectangle turns into a block: `DrawGlow` switches to the small halo for elements under 24 px.
- **Built-in tabs** (class names end with `MenuTab`: Among Us already has a global `AccountTab` type, which would win name resolution):

| Tab | Class | Content |
|-----|-------|---------|
| Account | `AccountMenuTab` | Connection status (connected + account / not connected / banned + reason), detected mod, GLMod version, server when not production. |
| Last game | `LastGameMenuTab` | `PlayerService.GetLastGame`, kept concise (little scrolling): result card (VICTORY / DEFEAT, date, "as <in-game name> · <mod> · S<season>", map / role pills); the boolean facts **only when true**, as colored tags (Ranked, First blood, Killed first, First victim, Killed, Exiled; a false value shows nothing); "View recap" → `Application.OpenURL(game.url)`; then every non-null numeric value in a 3-column `StatGrid` (duration, turns, meetings, players, ranking points, kills, double kills, time to first kill, tasks, task speed, death / exile turn, time / turns / meetings alive, good votes, key-meeting votes, skips, votes received, teammate votes, vote order / delay, bodies reported, self reports, report delay, emergencies). The `winners` list is not shown (the result already says it). When a game ends (`IGameHistoryService.EntryRecorded`) the tab is selected for the next opening and reloads every `LAST_GAME_POLL_SECONDS` until Good Loss returns that game id (at most `LAST_GAME_WAIT_SECONDS`), with a "still processing" note meanwhile. |
| Sessions | `SessionsMenuTab` | `PlayerService.GetSessions`: tiles (sessions, games played), then one row per session (start date, games, duration, LIVE / OPEN badge, "View" → session page). Invalidated when a game ends. |

API tabs load through `RemoteData<T>` (internal): cache per account, reload when shown after `MENU_REFRESH_SECONDS` (`MENU_RETRY_SECONDS` after an error), Loading / Offline / Unavailable states; the Unavailable state has a **Retry** button (forced reload). A live session (no end) shows its duration up to now.

- **Translations**: every text of the menu comes from `ITranslationService` (§3.12) and follows the game language, English otherwise.
- **Mods built on GLMod**: from their `Load()` (GLMod is loaded first, its built-in tabs already registered) or later, they can hide the menu, remove built-in tabs by id and add / insert their own tabs (§3.10); documented in `docs/dev.MD`. The Last game tab does not poll after a game when the menu is disabled or the tab was removed.

### 11.5 End-to-end test (4 Among Us instances, online lobby, 2 games)
- Project: [GLMod.TestHarness/](GLMod.TestHarness/) — a separate BepInEx plugin (`glmod.testharness`, depends on `glmod`). **Inert** unless the `GLMOD_TEST_INSTANCE` environment variable is set; it has no AfterBuild copy and is only installed in `Among Us/BepInEx/plugins/` for the duration of a run.
- Entry point: `powershell -ExecutionPolicy Bypass -File GLMod.TestHarness/run-e2e.ps1` (options: `-ApiEndpoint` (default `https://preprod.goodloss.fr/api`), `-ModName`, `-Map`, `-NoTile`, `-NoBuild`, `-KeepPlugin`, `-KeepOtherPlugins`, `-TimeoutSeconds`). Refuses to start if Among Us is already running.
- Plugin isolation: other mods change GLMod's mod name (e.g. ChallengerLevel sets "Challenger Maps", which the site records without a season). Unless `-KeepOtherPlugins`, the script moves every plugin except `GLMod.dll`, `GLMod.TestHarness.dll` and `Mini.RegionInstall.dll` (custom server region) to `BepInEx/plugins-disabled-by-e2e/` for the run and moves them back at the end, so the session runs as **Vanilla**.
- Mod and map: `-ModName` (default `Among Us Ranked`, applied by the harness through `GLMod.ConfigService.SetModName`, like a third-party mod; empty keeps GLMod's own name) and `-Map` (default `Polus`; `Keep` leaves the lobby setting). The host switches the lobby map (`IGameOptions.SetByte(MapId)` + `LogicOptions.SyncOptions`) and restores its saved map setting at the end. The site only draws the map visualization for maps it has an image for (`/images/maps/polusmap.png`, Challenger maps, Submerged…): **not for The Skeld**.
- Windows: the script tiles the 4 game windows in a 2×2 grid on the primary screen (`-NoTile` to disable) and restores Unity's `Screenmanager*` registry values (window size/position) afterwards.
- Recap check: preprod recaps can be read at `https://preprod.goodloss.fr/game/<id>` (SSO account provided by the maintainer). Expected on Polus: every action line timed, map visualization with all positions inside the game window, `completedTask` actions on the map. Known site-side gaps (data sent by GLMod but not shown): `SAB_START_*` / `SAB_END_*`, and ghost tasks (`tasksDead`) in the `x/y` task count.
- API: the script sets `GLMOD_API_ENDPOINT` for the 4 instances, so every match goes to the **preprod** API. All 4 instances share the local Steam / Good Loss account.
- Network: **online games** (RPCs behave differently from LAN). Instance 0 creates a game on the currently selected region (`AmongUsClient.CoCreateOnlineGame`) and publishes its code in `lobby-1.json`; instances 1–3 join it (`CoJoinOnlineGameFromCode`). The harness **refuses official Innersloth servers** (region name / ping server containing `among.us` or `innersloth`): use a custom region (e.g. Impranked).
- Session ([ScenarioPlan.cs](GLMod.TestHarness/ScenarioPlan.cs)); per game, crewmates sorted by player id → A, B, C:
  - **Game 1 — crewmates win by tasks**: B (tasker) plays one task; the impostor sabotages the lights (`RpcUpdateSystem(Sabotage, Electrical)`) and C fixes them at the panel (one `RpcUpdateSystem(Electrical, i)` per wrong switch, like the minigame); C presses the emergency button (`EmergencyMinigame.CallMeeting`); votes impostor + A → B, B + C → skip: **tie, nobody exiled**; the impostor kills A; every crewmate, including A **as a ghost**, plays all its remaining tasks.
  - **Return to the lobby**: everyone presses "Play Again" (`EndGameNavigation.NextGame`), the host first (it publishes `lobby-2.json` once back).
  - **Game 2 — impostor wins by vote**: the impostor kills A; B walks to the body and reports it (`ReportClosest`); votes impostor + B → C, C → impostor; C is exiled → 1 vs 1.
- Task play: for each step the player finds the step's console (`PlayerTask.FindConsoles`), moves there (`NetTransform.RpcSnapTo`), opens the minigame (`Console.Use`) and finishes it with `NormalPlayerTask.NextStep()` + `Minigame.Close()` (the last step sends `RpcCompleteTask` itself). The host makes the impostor kill (`RpcMurderPlayer`). Meetings wait for their "Proceed" button after the results, which the harness presses (`MeetingHud.HandleProceed`).
- Coordination: files in the run output folder (`lobby-N.json`, `plan-N.json`), no extra RPC.
- Verification ([ScenarioVerifier.cs](GLMod.TestHarness/ScenarioVerifier.cs), unit-tested), on the `GLGame` snapshot taken right after GLMod's `OnGameEnd`:
  - game 1: `completedTask`, `SAB_START_Lights` / `SAB_END_Lights`, `called an emergency` (turn 1); 4 `voted` incl. 2 skips (target `""`, turn 1001); no `exiled`; `killed` in turn 2; `turns` = `2`; per crewmate `tasks + tasksDead = tasksMax` and as many `completedTask` actions, the ghost only in `tasksDead`; winner `Crewmate`;
  - game 2: `killed`, `reported` (by a crewmate), 3 `voted`, `exiled` (a crewmate), winner `Impostor`, impostor `win=1`;
  - both: game id set, teams, `/game/end` succeeded on the host (step back to `Initial`), clients received the game id (RPC 1), game 2 has a **new** GLMod game id;
  - every instance, once its end screen is up: the game is the latest entry of the local history (the menu end-of-game signal, §3.9) with the recap link of the API's site (preprod), the map, the local player's team and the expected victory / defeat.
- Local history: the script moves the player's `BepInEx/config/glmod-history.json` aside for the run (`glmod-history.before-run.json` in the output folder) and puts it back at the end; the run's history is kept as `glmod-history.json` in the output folder.
- Multi-instance workarounds: 4 Unity instances on one machine stall for seconds on heavy frames (map load, meeting open) and vanilla Hazel timeouts then drop the client (`ReliablePacketWithoutResponse`): the harness raises `DisconnectTimeoutMs` / `MissingPingsUntilDisconnect` on the client connection. Clients must load the map within a hard-coded 10s (`AmongUsClient.MAX_CLIENT_WAIT_SECONDS` is a native constant: **writing it crashes the game**), so each instance caps its frame rate (20 fps) and sets `Application.backgroundLoadingPriority = High`. It also skips `CosmeticsCache.ClearUnusedCosmetics`, which intermittently throws inside `AmongUsClient.CoStartGame` in multi-instance runs (the client then never becomes ready and is kicked).
- Output: `GLMod.TestHarness/output/<date>-<runId>/` (gitignored) — `lobby-N.json`, `plan-N.json`, `result-N.json` (per-game results), `instance-N.log`, `player-N.log` (Unity log of each instance, via `-logFile`), copied BepInEx logs.
- Not covered: disconnections (relaunching clients is too slow), roles, impostor wins by kill / sabotage, shield T1.

### 12.1 Structure rules (NON-NEGOTIABLE)

1. **One service = one interface + one implementation**, in their respective folders.
2. **Naming**:
   - Interfaces: `I<Name>Service` or `I<Name>Manager`.
   - Implementations: `<Name>Service` / `<Name>Manager` (no `I`).
   - File = public class name (`PascalCase.cs`).
3. **Namespaces**:
   - `GLMod` — static facade.
   - `GLMod.Class` — utilities.
   - `GLMod.Constants` — constants.
   - `GLMod.Enums` — enumerations (+ extensions in the same file).
   - `GLMod.EventPatch` — Harmony patches.
   - `GLMod.Menu` — Good Loss menu (tab contract, widgets, behaviour, built-in tabs).
   - `GLMod.GLEntities` — DTOs / models.
   - `GLMod.Services.Interfaces` — contracts.
   - `GLMod.Services.Implementations` — logic.
4. **No business logic in `GLMod.cs`** — only bootstrap + a static facade over the services. Legacy methods (`StartGame`, `AddPlayer`, etc.) are nothing more than **wrappers** delegating to the services.
5. **No direct access to `HttpClient`** from a service — go through `ApiService` or `HttpHelper.Client`.
6. **No new `HttpClient` instance** — reuse the static `HttpHelper` instance.
7. **Every coroutine must be launched via `CoroutineRunner.Run(...)`** unless we are already inside an IL2CPP `MonoBehaviour`.
8. **Every new Harmony patch** goes into `GLMod/EventPatch/` with one file per patched Among Us class.
9. **Every new enum** goes into `GLMod/Enums/`, with its `<Enum>Extensions` extensions class in the same file when applicable.
10. **Every constant** goes into `GLMod/Constants/GameConstants.cs` — no magic strings/numbers scattered around.
11. **Every entity serialized to/from the API** goes into `GLMod/GLEntities/`, with `string` properties (see §4).

### 12.2 Code style
- **Indentation**: 4 spaces (default C# / VS).
- **Braces**: Allman style (brace on its own line).
- **`var`**: allowed for obvious types.
- **XML doc comments** (`/// <summary>`): **mandatory on every public method and property of a service interface**.
- **Logging**: inside a service, expose `private void Log(string message) => ServiceLogger.Log(_logger, nameof(<Service>), message);` and call `Log(...)` everywhere. The shared formatter ([GLMod/Class/ServiceLogger.cs](GLMod/Class/ServiceLogger.cs)) produces `[GLMod][ServiceName] PlayerName: message`. Outside of services, use `GLMod.log(...)`.
- **Exception handling**: `try/catch` around every call into the game / network / parser, log the exception, **never** silently rethrow in a way that would crash the game.
- **Language**: all identifiers, comments, and developer-facing strings MUST be in English (see §0).

## 13. Third-party integration (summary — details in `docs/dev.MD`)

A third-party mod consumes GLMod by:
1. Adding `GLMod.dll` to `BepInEx/plugins/`.
2. Creating an empty file `BepInEx/config/<MOD_NAME>.glmod`.
3. Calling `GLMod.ConfigService.SetModName("MOD_NAME")` in its `Load()`.
4. (Optional) Disabling the default services it wants to override: `GLMod.ServiceManager.DisableService(ServiceType.StartGame)` etc.
5. (Optional) Overriding the match lifecycle:
   - `GLMod.StartGame(code, map, ranked)`
   - `GLMod.AddPlayer(name, role, team)` for each player
   - `GLMod.SendGame()` + `GLMod.AddMyPlayer()` to validate
   - `GLMod.SetWinnerTeams(...)` + `GLMod.AddWinnerPlayer(...)` + `GLMod.EndGame()` at the end
6. Adding custom actions: `GLMod.addAction(source, target, action)`.
7. (Optional) Customizing the Good Loss menu through `GLMod.MenuService`: hide it (`Enabled = false`), remove built-in tabs (`UnregisterTab(GameConstants.MENU_TAB_SESSIONS)`…), add tabs (`RegisterTab(id, title, draw, onShown)` / `InsertTab(index, tab)`) drawn with the `GLMod.Menu.MenuUI` widgets.

> RPC **240** is **reserved** for GLMod. No third-party mod must use it.

## 15. Security & privacy

- **Identifier**: SteamID (only transmitted to `goodloss.fr` for authentication).
- **No password**: login = SteamID → Good Loss token.
- **`token.txt`, `output`, `server`** are gitignored (see `.gitignore`).
- **Ban**: handled server-side, HTTP 403 response + `"Banned: <reason>"`.
- **Integrity**: `IntegrityService` can verify a DLL's SHA against a remote checksum to detect mod tampering.
- **Local history**: `glmod-history.json` stays on the player's computer; it is never uploaded.
- **Menu**: never shows information that would help during a game (roles, teams, shield T1, other players' positions). The history only shows the local player's role once the game is over. The token is never displayed.

## 17. Known pitfalls / Points of attention

- **`GLMod.Version` vs csproj `<Version>` vs README badge**: the three must be identical. Any drift breaks display on the Good Loss side or misleads users about the installed version. The README badge URL is `https://img.shields.io/badge/GLMod-vX.Y.Z-blue` — update the `X.Y.Z` segment on every version bump.
- **csproj `<GameVersion>` vs README**: must point to the same Among Us version — a build against the wrong Among Us version will crash because of incompatible IL2CPP signatures.
- **`PlayerControl.LocalPlayer` may be `null`** at startup (pre-menu). Always use `?.` (see the pattern in every `Log(...)`).
- **IL2CPP**: any new `MonoBehaviour` must be registered with `ClassInjector.RegisterTypeInIl2Cpp<T>()` before instantiation.
- **`CurrentGame` may be `null`** between `EndGame()` and the next `StartGame()`. Always check before access.
- **Coroutines & threads**: **never** touch the Unity API from a `Task.Run` — only from the main thread (the `done` flag + `yield return null` pattern is there for that).
- **The `Among Us/` folder is gitignored** — every developer installs their own copy. Never commit this folder.
- **IL2CPP calls from worker threads crash the game** (access violation in `coreclr.dll`): `GameStateManager.SyncGameId` used to send RPC 1 from `Task.Run`, which intermittently killed the host right after `[makeRPC] 1`. RPCs and anything touching `AmongUsClient` / `PlayerControl` must be called from the coroutine itself (Unity main thread); `CoroutineHelpers.RunAsync` is for HTTP / pure .NET work only.
- **Client clock skew**: the site places actions and positions on the game timeline by comparing their timestamps with the server's own start/end times. With a wrong system clock (seen: 2h behind), the recap had no action times and no map data. Always timestamp with `ServerClock.NowMs()` (offset measured from API responses), never `DateTimeOffset.UtcNow`.
- **IMGUI methods stripped from the Among Us build**: `GUI.DrawTexture` (every overload) and the 4-argument `RectOffset` constructor exist in the interop assemblies but throw "Method unstripping failed" at runtime. Draw backgrounds with `GUI.Box` + a style background tinted by `GUI.backgroundColor` (`MenuUI.DrawRect`), and set `RectOffset` fields one by one. Verified working: `GUI.Label` / `Button` / `Box` / `BeginGroup` / `EndGroup`, `GUI.matrix`, `GUI.color`, `GUIStyle.CalcHeight` / `CalcSize`, `Event.current`, `Texture2D` creation + `SetPixel` + `Apply`, `Font.CreateDynamicFontFromOSFont` + `GUIStyle.font`, and `ScreenCapture.CaptureScreenshot` (captures the IMGUI overlay too: handy to check the menu without sending input to the game window).
- **`MonoBehaviour` messages (`Update`, `OnGUI`)**: attach the component with `BasePlugin.AddComponent<T>()` (BepInEx manager object). A component added in `Load()` to our own `new GameObject` + `DontDestroyOnLoad` never received `Update` / `OnGUI` (coroutines started on such an object do work, see `CoroutineRunner`).
- **Global Among Us type names**: Assembly-CSharp types live in the global namespace and win over `using` imports (e.g. Among Us's `AccountTab` hid `GLMod.Menu.AccountTab`). Give GLMod types distinctive names (`*MenuTab`).
- **Auto-generated `Resources.Designer.cs`**: regenerated by Visual Studio in the developer's UI culture and is the only file allowed to contain non-English content. Do not hand-edit; regenerate from a machine with an English UI if needed.
